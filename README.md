# bus-2.0 Go boilerplate

The starting point for every bus-2.0 Go microservice. It contains:

- **`platform/`**: a shared kit every service imports. It covers HTTP (Gin),
  auth, config, logging, errors, Postgres (ent), MongoDB, Redis, Kafka, the
  outbox/inbox and health checks. It contains no business logic.
- **`tools/scaffold`**: a generator that creates a new service with only the
  pieces it needs.
- **`services/`**: two working examples, generated by the same tool.
- **`docker-compose.yml`**: Postgres, MongoDB, Kafka, Kafka UI and Redis for
  local development.

Build, CI/CD and deployment belong to DevOps and are not part of this repo.

**Stack:** Go 1.26 · Gin · ent + PostgreSQL · MongoDB driver v2 · Kafka (franz-go) ·
Redis (go-redis v9) · slog → Graylog · Prometheus · OpenTelemetry.

## 1. Prerequisites

| Tool | Needed for |
|---|---|
| Go **1.26+** | everything (`go version`) |
| Docker + Docker Compose | local Postgres, Mongo, Kafka, Redis |
| `make` | the shortcuts below |
| [Atlas](https://atlasgo.io/getting-started) (optional) | Postgres migrations: `curl -sSf https://atlasgo.sh \| sh` |
| `golangci-lint` (optional) | `make lint` |

## 2. First-time setup

```bash
git clone git@github.com:Sadiquzzaman/bus-2.0-go-boilerplate.git
cd bus-2.0-go-boilerplate

make bootstrap   # downloads dependencies, runs ent codegen, go mod tidy, build, unit tests
make up          # starts postgres, mongo, kafka, kafka-ui, redis (waits until healthy)
```

`make bootstrap` is safe to re-run. Commit the `go.mod`, `go.sum` and generated
`services/*/ent` code it produces.

Local infrastructure:

| Service | Address | Notes |
|---|---|---|
| Postgres | `localhost:5432` | user/password `postgres` / `postgres` |
| MongoDB | `localhost:27017` | single-node replica set `rs0`, so transactions work |
| Kafka | `localhost:9092` | topics are **not** auto-created (same as shared environments) |
| Kafka UI | http://localhost:8085 | browse topics and messages |
| Redis | `localhost:6379` | |

## 3. Run the examples

`example-pg` (Postgres + Kafka + Redis) creates items and publishes `item.created`
events through the outbox. `example-mongo` (Mongo + Kafka) consumes those events.

```bash
# 1. env files (git-ignored copies of the examples)
cp services/example-pg/.env.example    services/example-pg/.env
cp services/example-mongo/.env.example services/example-mongo/.env

# 2. Postgres schema for example-pg (first time only; needs atlas + docker)
make migrate-diff svc=example-pg name=init
make migrate-up   svc=example-pg

# 3. Kafka topics
make run svc=example-pg    mode=topics
make run svc=example-mongo mode=topics

# 4. run both (two terminals)
make run svc=example-pg    mode=all     # API :8080, admin :8081
make run svc=example-mongo mode=all     # API :8090, admin :8091
```

Try it:

```bash
CID=0190a8f0-0000-7000-8000-000000000001   # any UUID works as a company locally

# create
curl -s -X POST localhost:8080/v1/items \
  -H "X-Company-ID: $CID" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"name":"Dhaka → Chattogram","description":"night coach"}'
# {"data":{"id":"0192…","company_id":"0190a8f0-…","name":"Dhaka → Chattogram","status":"ACTIVE",…}}

# list (paged) and get
curl -s "localhost:8080/v1/items?page=1&limit=20" -H "X-Company-ID: $CID"
curl -s localhost:8080/v1/items/<id> -H "X-Company-ID: $CID"

# archive (records are never deleted)
curl -s -X POST localhost:8080/v1/items/<id>/archive -H "X-Company-ID: $CID"

# health and metrics
curl -s localhost:8081/readyz
curl -s localhost:8081/metrics | grep http_server
```

What you'll see:

- **example-pg log:** `http request … status=201`, then the relay publishes
  the outbox row.
- **Kafka UI:** a message on `example-pg.item.v1` with the standard envelope.
- **example-mongo log:** `item event processed … producer=example-pg`.
- **Error cases:**
  - no `X-Company-ID` → `400 BAD_REQUEST`
  - empty name → `422 VALIDATION_FAILED` with field details
  - another company's item ID → `404`

Locally, `AUTH_ENABLED=false` so no token is needed. Pass `X-Dev-User-ID: u1` to
pretend to be a user.

## 4. Create a new service

```bash
make new-service name=<name> db=<db> kafka=<true|false> redis=<true|false>
```

| Option | Values | Default |
|---|---|---|
| `name` | lowercase, digits, dashes: `booking`, `seat-inventory` | required |
| `db` | `postgres` · `mongo` · `postgres,mongo` · `none` | `postgres` |
| `kafka` | publish events (outbox) + consume events | `true` |
| `redis` | cache, `Idempotency-Key`, locks, rate limits | `true` |

Examples:

```bash
# Transactional service: Postgres, events, cache
make new-service name=booking db=postgres kafka=true redis=true

# Document service that reacts to events, no cache
make new-service name=notification db=mongo kafka=true redis=false

# Two databases: Postgres for transactions, Mongo for documents/read models
make new-service name=search db=postgres,mongo kafka=true redis=true

# No database: an API that only aggregates other services, cached in Redis
make new-service name=gateway db=none kafka=false redis=true

# No database, no HTTP state: a pure event processor
make new-service name=fare-calculator db=none kafka=true redis=false
```

The generator writes `services/<name>/`, runs ent codegen for Postgres services
and `go mod tidy`, then prints the next steps. A typical first run:

```bash
cp services/booking/.env.example services/booking/.env
make db svc=booking                              # Postgres only: create the database
make migrate-diff svc=booking name=init          # Postgres only
make migrate-up   svc=booking
make run svc=booking mode=topics                 # Kafka only
make run svc=booking mode=all
```

Each new service gets the next free local port pair (8100/8101, 8110/8111, …).
Change `HTTP_ADDR` / `APP_ADMIN_ADDR` in `.env` if you like.

**What each `db` choice gives you:**

| `db=` | Generated |
|---|---|
| `postgres` | ent schema + `internal/store/postgres`, Atlas migrations, outbox/inbox tables |
| `mongo` | `internal/store/mongo` with indexes, outbox/inbox collections |
| `postgres,mongo` | everything from `postgres`. Mongo is a **secondary** database: `Deps.Mongo(ctx)` in bootstrap, plus a sample `internal/store/activity` that writes one Mongo document per consumed event. Postgres stays the source of truth and holds the outbox/inbox. |
| `none` | no store, no domain/service layer: just the HTTP API (`/v1/me`) and, with Kafka, a consumer |

A service compiles only what it uses. A Mongo-only service has no ent/pgx in its
binary, and a Postgres-only service has no Mongo driver.

## 5. Anatomy of a service

```
services/booking/
├── cmd/booking/main.go          entry point; registers run modes
├── internal/
│   ├── config/config.go         env config: platform configs + your own `Service` struct
│   ├── bootstrap/bootstrap.go   wiring: opens DB/Redis/Kafka lazily per run mode
│   ├── api/http.go              Gin routes, request binding, permission checks
│   ├── domain/                  business types (no framework imports)
│   ├── service/                 business logic + unit tests with an in-memory fake store
│   ├── store/postgres|mongo/    persistence behind the service.Store interface
│   ├── events/events.go         topics this service owns, event types, payloads
│   └── consumer/consumer.go     Kafka handlers (idempotent via inbox)
├── ent/schema/                  ent schema (Postgres)
├── migrations/                  Atlas SQL migrations (Postgres)
├── atlas.hcl                    (Postgres)
├── .env.example
└── README.md
```

Dependencies only point inward: `api → service → Store interface ← store/<db>`.
The `service` package never imports Gin, ent or the Mongo driver, so the same
business code works on either database and is unit-tested without one.

**Run modes.** One binary, the first argument picks what runs:

| Mode | What runs |
|---|---|
| `api` | public HTTP server (`HTTP_ADDR`, default `:8080`) |
| `relay` | outbox → Kafka publisher (one leader; extra replicas wait as standby) |
| `consumer` | Kafka consumer group |
| `topics` | create the service's Kafka topics, then exit (local only) |
| `all` | api + relay + consumer in one process (local only) |

Every long-running mode also serves `/livez`, `/readyz` and `/metrics` on
`APP_ADMIN_ADDR` (default `:8081`).

The generated `Item` entity is a **sample**. Rename or replace it; keep the patterns.

## 6. Walkthrough: add a `Trip` entity

Example for a Postgres service named `booking`.

**1. Schema:** `services/booking/ent/schema/trip.go`

```go
package schema

import (
	"entgo.io/ent"
	"entgo.io/ent/schema/field"
	"entgo.io/ent/schema/index"

	"github.com/Sadiquzzaman/bus-2.0-go-boilerplate/platform/postgres/entx"
)

type Trip struct{ ent.Schema }

// IDMixin: UUIDv7 id. TimeMixin: created_at/updated_at.
// ScopeMixin: company_id/vertical_id/tenant_id + automatic company filtering.
func (Trip) Mixin() []ent.Mixin {
	return []ent.Mixin{entx.IDMixin{}, entx.TimeMixin{}, entx.ScopeMixin{}}
}

func (Trip) Fields() []ent.Field {
	return []ent.Field{
		field.String("route_code").NotEmpty(),
		field.Time("departs_at"),
		field.Int("total_seats").Positive(),
		field.String("status").Default("SCHEDULED"),
	}
}

func (Trip) Indexes() []ent.Index {
	return []ent.Index{index.Fields("company_id", "departs_at")}
}
```

**2. Generate code and a migration:**

```bash
make gen
make migrate-diff svc=booking name=add_trips   # writes migrations/<timestamp>_add_trips.sql
make migrate-up   svc=booking
```

**3. Domain type and repository.** Add `domain.Trip`, a `TripRepository`
interface in `service/store.go`, and add it to `Repos`. Implement it in
`store/postgres` the same way `itemRepo` is implemented:

```go
func (r tripRepo) Create(ctx context.Context, t domain.Trip) (domain.Trip, error) {
	e, err := r.c.Trip.Create().
		SetRouteCode(t.RouteCode).
		SetDepartsAt(t.DepartsAt).
		SetTotalSeats(t.TotalSeats).
		Save(ctx) // company_id is filled from the request scope automatically
	if err != nil {
		return domain.Trip{}, mapErr(err)
	}
	return toDomainTrip(e), nil
}
```

**4. Business logic + event**, in `service/trip.go`:

```go
func (s *TripService) Schedule(ctx context.Context, in ScheduleTripInput) (domain.Trip, error) {
	if in.TotalSeats <= 0 {
		return domain.Trip{}, apperror.Validation(apperror.FieldError{Field: "total_seats", Message: "must be positive"})
	}
	var out domain.Trip
	err := s.store.Tx(ctx, func(ctx context.Context, r Repos) error {
		t, err := r.Trips.Create(ctx, domain.Trip{RouteCode: in.RouteCode, DepartsAt: in.DepartsAt, TotalSeats: in.TotalSeats})
		if err != nil {
			return err
		}
		out = t
		env, err := kafka.NewEnvelope(ctx, kafka.Event{
			Type: "trip.scheduled", Version: 1,
			AggregateType: "trip", AggregateID: t.ID,
			Payload: t,
		})
		if err != nil {
			return err
		}
		return r.Outbox.Add(ctx, "booking.trip.v1", env) // same transaction as the insert
	})
	return out, err
}
```

**5. HTTP route**, in `api/http.go`:

```go
trips := r.Group("/trips", httpserver.RequireCompany())
trips.POST("", auth.RequirePermission(h.authz, "booking.trip.write"), h.scheduleTrip)

type scheduleTripRequest struct {
	RouteCode  string    `json:"route_code" binding:"required"`
	DepartsAt  time.Time `json:"departs_at" binding:"required"`
	TotalSeats int       `json:"total_seats" binding:"required,min=1,max=80"`
}

func (h *Handler) scheduleTrip(c *gin.Context) {
	var req scheduleTripRequest
	if !httpserver.BindJSON(c, &req) { // writes 400/422 itself
		return
	}
	t, err := h.trips.Schedule(c.Request.Context(), service.ScheduleTripInput{
		RouteCode: req.RouteCode, DepartsAt: req.DepartsAt, TotalSeats: req.TotalSeats,
	})
	if err != nil {
		httpserver.Fail(c, err) // maps apperror → status + JSON
		return
	}
	httpserver.Created(c, t)
}
```

**6. Register the topic.** Add `"booking.trip.v1"` to `OwnTopics` in
`internal/events/events.go` (so `mode=topics` creates it locally), and tell
DevOps about the new topic.

**7. Consume it elsewhere.** In another service's `consumer/consumer.go`:

```go
func (h *Handlers) Router() *kafka.Router {
	return kafka.NewRouter().Handle("trip.scheduled", h.onTripScheduled)
}

func (h *Handlers) onTripScheduled(ctx context.Context, msg *kafka.Message) error {
	var t struct {
		ID        string `json:"id"`
		RouteCode string `json:"route_code"`
	}
	if err := msg.Decode(&t); err != nil {
		return err // bad payload → dead-letter topic, no retries
	}
	return h.store.Tx(ctx, func(ctx context.Context, r service.Repos) error {
		dup, err := r.Inbox.Claim(ctx, "inventory.trip-events", msg.EventID)
		if err != nil || dup {
			return err // already processed → skip
		}
		// … create seat inventory for t.ID using r …
		return nil
	})
}
```

Then set `CONSUMER_TOPICS=booking.trip.v1` in that service's `.env`.

## 7. Using the platform kit

Short recipes. Every package also has doc comments with more detail.

**Logging:** always pass the context. Request ID, correlation ID, company and
actor are added automatically, and secrets are redacted.

```go
slog.InfoContext(ctx, "seat held", slog.String("seat_id", id), slog.Duration("ttl", ttl))
slog.ErrorContext(ctx, "payment failed", logger.Err(err))
```

**Errors:** return `apperror` values; `httpserver.Fail` turns them into the standard JSON.

```go
return apperror.NotFound("trip not found")
return apperror.Conflict("seat already booked")
return apperror.Validation(apperror.FieldError{Field: "phone", Message: "is invalid"})
return apperror.Internal("could not reach payment gateway").Wrap(err) // cause is logged, not returned
```

**Request scope:** comes from the `X-Company-ID` / `X-Vertical-ID` / `X-Tenant-ID` headers.

```go
s, _ := reqctx.ScopeFrom(ctx)       // s.CompanyID, s.VerticalID, s.TenantID
ctx = reqctx.WithoutScopeFilter(ctx) // system jobs only: skip automatic company filtering
```

**Permissions:**

```go
r.POST("/trips", auth.RequirePermission(authz, "booking.trip.write"), h.create) // 403 if not allowed
r.GET("/trips", auth.LoadAccessList(authz, "booking.trip.read"), h.list)        // visible verticals/tenants
p, _ := auth.PrincipalFrom(ctx)                                                 // p.Subject, p.IsService()
```

**Publishing directly** (no outbox; only for events you can afford to lose on a crash):

```go
env, _ := kafka.NewEnvelope(ctx, kafka.Event{Type: "otp.requested", AggregateID: phone, Payload: p})
err := producer.Publish(ctx, "iam.otp.v1", env)
```

**Calling another service** (GET only; writes go through Kafka). First add
`HTTPClient httpclient.Config \`envPrefix:"HTTPCLIENT_"\`` and
`Credentials httpclient.CredentialsConfig \`envPrefix:"OAUTH_"\`` to your config:

```go
trips := httpclient.New("trip", "http://trip:8080", cfg.HTTPClient, cfg.Credentials.TokenSource("trip-api"))
var t TripDTO
err := trips.GetJSON(ctx, "/v1/trips/"+id, nil, &t) // retries, circuit breaker, headers forwarded
```

**Redis:**

```go
v, err := redis.Remember(ctx, rdb, rdb.Key("route", companyID, code), 5*time.Minute,
	func(ctx context.Context) (Route, error) { return repo.Route(ctx, code) })

lock, err := rdb.TryLock(ctx, rdb.Key("seat", tripID, seatNo), 10*time.Minute) // seat hold
if errors.Is(err, redis.ErrLockNotAcquired) { /* someone else holds it */ }
defer lock.Unlock(ctx)

res, _ := rdb.Allow(ctx, rdb.Key("otp", phone), 3, time.Hour) // 3 per hour
if !res.Allowed { return apperror.RateLimited("try again later") }
```

**Second database** (`db=postgres,mongo`):

```go
mdb, err := d.Mongo(ctx)                // in bootstrap; connects on first use
coll := mdb.DB.Collection("trip_search")
f, err := mongo.Scoped(ctx, bson.D{{Key: "route_code", Value: code}}) // adds company_id
```

## 8. Add something later

The generator is for day one. To add a piece to an existing service, copy the
matching parts from a service generated with that option (or from the
examples):

| Add | Steps |
|---|---|
| **Redis** | add `Redis redis.Config \`envPrefix:"REDIS_"\`` to `config.go`; add the `Redis()` getter from `example-pg`'s bootstrap; add `REDIS_ADDRS` to `.env` |
| **Mongo to a Postgres service** | add `Mongo mongo.Config \`envPrefix:"MONGO_"\`` to `config.go`; add the `Mongo()` getter to bootstrap; add `MONGO_URI`, `MONGO_DATABASE` to `.env` |
| **Kafka** | copy `internal/events`, `internal/consumer`, the Kafka parts of config/bootstrap, and (to publish) `ent/schema/messaging.go` + the outbox/inbox parts of the store, then `make gen` and a migration |

Tip: to see exactly what to copy, generate a throw-away service with the
option you want (`make new-service name=tmp db=postgres,mongo`), compare it
with yours, then delete `services/tmp`.

## 9. Configuration reference

All configuration is environment variables (a `.env` file in the service folder
is read locally). Startup fails if a required value is missing.

| Prefix | Examples | Package |
|---|---|---|
| `APP_` | `APP_NAME` (required), `APP_ENV` = local/staging/production, `APP_ADMIN_ADDR`, `APP_SHUTDOWN_DELAY_SECONDS` | `platform/config` |
| `LOG_` | `LOG_LEVEL` = debug/info/warn/error, `LOG_FORMAT` = json/text, `LOG_REDACT_KEYS` | `platform/logger` |
| `HTTP_` | `HTTP_ADDR`, `HTTP_REQUEST_TIMEOUT`, `HTTP_MAX_BODY_BYTES`, `HTTP_CORS_ALLOWED_ORIGINS` | `platform/httpserver` |
| `AUTH_` | `AUTH_ENABLED`, `AUTH_JWKS_URL`, `AUTH_ISSUER`, `AUTH_AUDIENCE`, `AUTH_AUTHORIZER` = allow-all/iam | `platform/auth` |
| `POSTGRES_` | `POSTGRES_DSN` (required), `POSTGRES_MAX_OPEN_CONNS`, `POSTGRES_DEBUG` | `platform/postgres` |
| `MONGO_` | `MONGO_URI`, `MONGO_DATABASE` (both required) | `platform/mongo` |
| `REDIS_` | `REDIS_ADDRS`, `REDIS_PASSWORD`, `REDIS_MASTER_NAME` (Sentinel), `REDIS_CLUSTER_MODE` | `platform/redis` |
| `KAFKA_` | `KAFKA_BROKERS`, `KAFKA_SASL_MECHANISM`, `KAFKA_SASL_USERNAME`, `KAFKA_SASL_PASSWORD`, `KAFKA_TLS` | `platform/kafka` |
| `CONSUMER_` | `CONSUMER_TOPICS` (comma separated) | service config |
| `OUTBOX_` | `OUTBOX_BATCH_SIZE`, `OUTBOX_POLL_INTERVAL`, `OUTBOX_RETENTION` | `platform/outbox` |
| `OTEL_` | `OTEL_TRACING_ENABLED`, `OTEL_EXPORTER_OTLP_ENDPOINT` | `platform/observability` |

Safety rails: `AUTH_ENABLED=false` is refused in staging/production, and
`AUTH_AUTHORIZER=allow-all` is refused in production. Plug in the IAM client in
`platform/auth/authorizer.go` when the IAM team publishes it.

Service-specific settings go in the `Service` struct in `internal/config/config.go`:

```go
type Service struct {
	SeatHoldTTL time.Duration `env:"SEAT_HOLD_TTL" envDefault:"10m"` // SERVICE_SEAT_HOLD_TTL
}
```

## 10. Make targets

| Target | What it does |
|---|---|
| `make help` | list targets |
| `make bootstrap` | deps + codegen + tidy + build + test |

| `make test` / `make lint` / `make fmt` | tests / lint / format |
| `make build` | build every service binary into `bin/` |

## 11. Troubleshooting

| Symptom | Fix |
|---|---|
| `go: go.mod requires go >= 1.26` | install Go 1.26+, or let `GOTOOLCHAIN=auto` download it |
| `cannot find package …/ent/item` | ent code not generated yet: `make gen` |
| `entx: company scope missing from context` | the request has no `X-Company-ID`, or a background job needs `reqctx.WithoutScopeFilter(ctx)` |
| Mongo: `Transaction numbers are only allowed on a replica set` | use the compose Mongo (replica set) and keep `replicaSet=rs0&directConnection=true` in `MONGO_URI` |
| Kafka: `UNKNOWN_TOPIC_OR_PARTITION` | create topics: `make run svc=<svc> mode=topics` |
| Events stay in `outbox_events` | the `relay` mode isn't running (use `mode=all` locally) |
| `make: *** missing separator` | the Makefile lost its tab characters; recipe lines must start with a tab |
| `relation "items" does not exist` | run `make migrate-diff …` / `make migrate-up svc=…` |
